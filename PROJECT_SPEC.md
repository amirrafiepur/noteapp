# Project Specification — Django Windows Desktop Note Prototype

## Project Goal

Build a local Django-based note/text management application.

The application will initially run as a local Django application.

In a later phase, it will be wrapped inside a Windows desktop application using:

Django
→ PySide6
→ Qt WebEngine
→ PyInstaller

The current phase is ONLY the Django prototype.

Do not implement PySide6, Qt WebEngine, or PyInstaller yet.

---

## Current Features

The prototype must contain:

1. User registration
2. User login
3. User logout
4. Dashboard
5. Create a new text
6. Store texts in SQLite
7. Display saved texts
8. Open a saved text
9. Print a saved text
10. Browser-compatible PDF/print functionality

---

## Authentication

Use Django's built-in authentication system.

Do not create a custom authentication system.

Users must be able to:

- Create an account
- Login
- Logout

Passwords must be handled by Django's built-in password hashing.

Protected pages must require authentication.

Each user must only be able to access their own texts.

---

## Dashboard

After login, the user enters the main dashboard.

The dashboard contains two main sections:

### New Text

A form for creating a new text.

### Saved Texts

A list of previously saved texts.

The interface should visually present these as two main panels.

---

## Text Model

Each text must contain:

- Owner/User
- Text content
- Creation date/time

The creation timestamp must be generated by the application.

Users must never be able to choose another user as the owner.

---

## Saved Texts

Display the authenticated user's saved texts.

Each item should show:

- Text preview/content
- Creation date/time

Newest texts should appear first.

Clicking a text opens its detail page.

---

## Text Detail

The detail page must display:

- Complete text
- Creation date/time
- Print button

The user must only be able to access their own texts.

Changing a note ID in the URL must not allow access to another user's text.

---

## Printing

The prototype should use a browser-compatible printing approach.

The detail page should provide a Print button.

The print version should contain only the relevant text and date, without unnecessary application navigation.

The browser print dialog is acceptable for the prototype.

Later, the Windows desktop version may use Qt's printing and PDF capabilities.

Do not add a PDF library unless it becomes necessary.

---

## Visual Design

Primary colors:

- Red
- Yellow
- White

The UI should be:

- Clean
- Simple
- Desktop-oriented
- Practical
- RTL-friendly
- Persian-oriented

Use Django Templates, HTML, CSS and minimal vanilla JavaScript.

Do not introduce React, Vue, Angular, or another frontend framework.

---

## Database

Use SQLite for the prototype.

Use Django ORM.

The main application model is `Note`.

The Note model should have:

- owner
- content
- created_at

Use a ForeignKey to Django's user model.

---

## Django Architecture

Use two Django applications:

### accounts

Responsible for:

- Registration
- Login
- Logout

### notes

Responsible for:

- Note model
- Dashboard
- Create note
- List notes
- Note detail
- Print

Do not create additional Django apps unless explicitly requested.

---

## Security

The application must:

- Use Django authentication
- Use CSRF protection
- Protect authenticated pages
- Filter notes by the authenticated user
- Never trust a client-supplied owner
- Never store plaintext passwords

For note access, use ownership filtering such as:

get_object_or_404(Note, pk=pk, owner=request.user)

---

## Development Rules

Development must happen incrementally.

For every phase:

1. Inspect the existing project.
2. Make the smallest required changes.
3. Run appropriate checks.
4. Verify the result.
5. Report what changed.
6. Do not jump ahead to future phases.

Do not rewrite working code unnecessarily.

Do not add dependencies without justification.

---

## Current Phase Restriction

Currently we are building ONLY the Django prototype.

Do NOT implement:

- PySide6
- Qt WebEngine
- PyInstaller
- Windows installer
- Desktop shortcuts
- Accounting modules
- Cloud services
- APIs
- React/Vue/Angular
- Unnecessary third-party libraries

These belong to future phases.
